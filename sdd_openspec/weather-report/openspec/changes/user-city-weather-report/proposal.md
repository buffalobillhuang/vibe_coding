## Why / 为什么

本变更希望提供“用户自选城市天气报告”能力，让用户可以根据自己关心的任意城市查询天气，而不是被固定在某个默认或隐式位置上。这样可以更好地覆盖跨城市生活、差旅出行等场景，提升产品的通用性和实际使用价值。

## What Changes / 会有哪些变化

- 新增城市搜索与选择的前端交互流程，支持用户按城市名称搜索并从候选列表中选择目标城市。
- 在选择城市后，展示该城市的天气报告，至少包括当前天气（温度、天气描述），如条件允许可附带短期预报信息。
- 记住用户上一次选择的城市（例如通过本地存储或应用内状态），在用户下次进入时默认展示最近一次选择的城市天气。
- 处理城市不存在、搜索无结果、网络/API 调用失败等异常与空状态，并以清晰、友好的方式提示用户。
- 在天气报告界面中展示一个可交互的 3D 地球，将用户当前选中的城市以明显标记形式高亮出来，增强空间感与可视化效果。

## Capabilities / 能力

### New Capabilities / 新增能力
- `user-city-weather-report`：支持用户搜索并选择城市，查看所选城市的当前天气与简要预报，并以清晰、聚焦的视图进行展示；同时在 3D 地球视图中高亮显示该城市的大致地理位置。

### Modified Capabilities / 修改的能力
- `<existing-name>`：说明该已有能力的哪些“需求级”行为发生了变化（如当前没有可留空或删除此项）。

## Impact / 影响范围

- 前端 / UI：新增或改造用于城市搜索、城市选择以及天气展示的页面／组件。
- 数据 / API：使用或扩展天气服务 API，支持按城市名称或城市标识进行天气查询。
- 状态与存储：设计并实现“最近一次选择城市”的存储与读取策略（例如浏览器本地存储或应用全局状态）。
- 错误处理：明确天气相关错误（API 失败、无效城市、限流等）的统一反馈方式和展示样式。
