# 需求规格模板（所有项目必遵循的白板规则）

> **语言要求**：所有需求文档、Spec 说明、Delta 变更内容一律使用**简体中文**撰写；  
> 仅在接口字段名、枚举值、代码标识符等必须保持英文时，可以保留英文。

## 1. 需求名称
[在这里填写需求名称，例如：用户自选城市天气报告]

## 2. 需求类型 → Spec 的流程
[填写类型，例如：新功能 / 优化 / Bug 修复 → 对应的完整 Spec 流程]

## 3. 业务场景
[用中文描述实际业务使用场景：谁在什么场景下，以怎样的频率使用这个功能]

## 4. 需求方
[谁提出的需求，例如：张三 / 某业务团队 / 外部合作方]

## 5. 优先级
[高 / 中 / 低，并可补充优先级排序的依据]

## 6. 背景
[为什么要做这个需求？问题来源、现状痛点是什么，用中文清晰阐述]

## 7. 目的
[达成什么目标？业务价值、用户价值分别是什么]

## 8. 具体内容（可配合 Excel）
[详细功能描述、字段定义、流程图、状态机、边界条件等。  
若有需要导出的 Excel、表头字段说明等，也在此处用中文说明清楚。]

## 9. 是否同步 / 依赖
[是否需要与其他系统或团队同步？有哪些模块、项目或版本依赖关系]

## 10. 历史数据
[相关历史数据、旧版本行为、迁移策略、灰度与回滚方案等]
